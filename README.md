# Сервис такси

Учебный сервис программы по проектированию систем Хекслета. Один сервис развивается на протяжении четырёх курсов.

| Курс | Каталог |
| --- | --- |
| Монолитное приложение | [monolith](./monolith) |
| События и стриминг | Материалы появятся по мере разработки курса |
| Распределённая система | Материалы появятся по мере разработки курса |
| Глобальная система | Материалы появятся по мере разработки курса |

## Монолитное приложение

В каталоге [monolith](./monolith) лежит работающий сервис заказа поездок вместе со стендом. Это же стартовый набор проекта «Сервис такси под нагрузкой», и студент копирует его содержимое в корень своего репозитория.

Сервис работает с выключенными механизмами защиты. Индексов сверх первичных ключей нет, ожидание сервиса уведомлений ничем не ограничено, очередь запросов не имеет предела, копия базы стоит рядом и не используется. Что из этого менять и в каком порядке, решают по замеру.

Механизмы таймаутов, повторов, ограничения нагрузки, кэширования, чтения с копии и вывода экземпляра из работы уже встроены в сервис. Их включает файл _monolith/service.env_. Для обязательного маршрута проекта студент меняет настройки, SQL-миграции и nginx. Знание TypeScript не требуется.

### Запуск

```bash
cd monolith
make up
```

Сервис поднимается на `http://localhost:8080` через балансировщик. Порт меняется переменной `WEB_PORT`. Схема и учебные данные накатываются при первом запуске базы, миграции применяет цель `make up`.

```bash
curl -s localhost:8080/health
curl -s localhost:8080/trips/1
```

### Что где лежит

| Путь | Назначение |
| --- | --- |
| [docker-compose.yml](./monolith/docker-compose.yml) | стенд, то есть два экземпляра приложения, база, копия базы, балансировщик, стаб уведомлений и генератор нагрузки |
| [service.env](./monolith/service.env) | переключатели и численные пределы поведения сервиса |
| [src/](./monolith/src) | приложение на TypeScript, запускается нодой без сборки |
| [db/schema.sql](./monolith/db/schema.sql) | базовые таблицы пассажиров, водителей, поездок и истории |
| [db/seed.sql](./monolith/db/seed.sql) | учебные данные, 20 тысяч поездок |
| [db/seed-large.sql](./monolith/db/seed-large.sql) | два миллиона поездок для замеров, заливается целью `make seed-large` |
| [db/migrations/](./monolith/db/migrations) | изменения схемы поверх базовой |
| [load/first-load.ts](./monolith/load/first-load.ts) | первый пример k6 с двумя виртуальными клиентами |
| [load/read.ts](./monolith/load/read.ts) | чтение поездки с постоянной частотой |
| [load/mixed.ts](./monolith/load/mixed.ts) | профиль сервиса, то есть заказы, чтения, координаты и история одновременно |
| [load/data-access.ts](./monolith/load/data-access.ts) | профиль истории, геопоиска и поиска поддержки для сравнения индексов |
| [load/profile.json](./monolith/load/profile.json) | частоты и цели, из которых сценарии берут числа |
| [nginx/nginx.conf](./monolith/nginx/nginx.conf) | балансировщик перед двумя экземплярами стенда |
| [nginx/local.conf](./monolith/nginx/local.conf) | тот же балансировщик для запуска на хосте без compose, его разбирает урок о масштабировании |
| [stub/index.ts](./monolith/stub/index.ts) | стаб сервиса уведомлений с настраиваемой задержкой и долей отказов |

### Операции сервиса

| Метод и путь | Назначение |
| --- | --- |
| `GET /health` | готовность экземпляра |
| `GET /metrics` | счётчики запросов, ожидания пула, времени SQL |
| `POST /trips` | создать заказ, обязателен заголовок `Idempotency-Key` |
| `GET /trips/{id}` | прочитать поездку |
| `POST /trips/{id}/accept` | назначить водителя |
| `POST /trips/{id}/cancel` | отменить поездку |
| `GET /trips/search?q=` | найти поездку по адресу |
| `POST /drivers/{id}/location` | обновить координаты водителя |
| `GET /drivers/nearby?lat=&lon=&radius=` | свободные водители рядом |
| `GET /passengers/{id}/trips` | история пассажира |
| `GET /tariffs/{code}` | тариф |

### Нагрузка

```bash
make load PROFILE=read                          # чтение с постоянной частотой
make load PROFILE=mixed                         # профиль сервиса
make load PROFILE=mixed SCALE=40 NAME=overload  # поиск предела
```

Цель пишет отчёт с условиями опыта в `reports/` и сохраняет сводку k6 рядом в JSON. Сценарий запускается контейнером, поэтому k6 на машину ставить не нужно.

### База отдельно от стенда

SQL-примеры уроков можно выполнять в учебной базе без стенда.

```bash
createdb taxi_development
psql -d taxi_development -v ON_ERROR_STOP=1 -f monolith/db/schema.sql
psql -d taxi_development -v ON_ERROR_STOP=1 -f monolith/db/seed.sql
```

Для примеров с геопоиском понадобится расширение PostGIS.
