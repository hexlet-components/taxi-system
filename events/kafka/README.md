# Порядок записей с ключом в Kafka

Окружение воспроизводит Java-пример урока «Порядок и параллелизм в Kafka». Программа создаёт топик с двумя партициями, публикует четыре записи с ключами двух поездок и читает обе партиции. Исходник находится в _src/main/java/KeyedTripsDemo.java_. Зависимости закреплены в _pom.xml_.

Команды выполняются из каталога _events/kafka/_ репозитория [taxi-system](https://github.com/hexlet-components/taxi-system). На компьютере установлен Docker с Docker Compose. При первом запуске Maven скачивает зависимости.

```bash
docker compose -p lesson-keyed-trips up -d --wait kafka
docker compose -p lesson-keyed-trips run --rm java
```

Java работает в отдельном контейнере, поэтому адрес брокера берётся из переменной `KAFKA_BOOTSTRAP_SERVERS` и равен `kafka:9092`. При запуске программы с хоста без этой переменной используется `localhost:9092`. Для такого запуска нужен отдельно доступный по этому адресу брокер.

Вывод содержит четыре строки `saved` и четыре строки `read`. У каждой поездки обе версии находятся в одной партиции, а offset более поздней версии больше. Разные ключи могут попасть в одну партицию. Порядок строк между партициями не задаёт общего порядка событий.

При каждом запуске программа создаёт топик с новым именем, чтобы прежние записи не влияли на результат. В течение 30 секунд она должна получить четыре записи, иначе завершится с ошибкой. Это проверка маршрутизации и чтения, программа не обновляет историю поездок и не проверяет восстановление после отказов.

После проверки команда ниже завершает контейнеры и удаляет тома только этого учебного проекта, включая кеш Maven.

```bash
docker compose -p lesson-keyed-trips down -v
```
