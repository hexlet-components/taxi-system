# Изолированный опыт Kafka и ClickHouse

Окружение дополняет урок «Доставка из Kafka в ClickHouse» (`sink-delivery`). Стенд содержит один брокер и один сервер ClickHouse, работает без публикации портов компьютера и не моделирует отказ узла. Нужны Docker с Compose и доступ к загрузке образов.

Команды подготовки и прохождения опыта находятся в README урока. Они выполняются из этого каталога. Имена сервисов и проект sd-stream-sink отделяют стенд от других учебных приложений.

Для SQL-опытов уроков «Аналитическая модель поездок» (`analytical-model`) и «Перестроение и развитие витрины» (`replay`) достаточно сервера ClickHouse. Из этого каталога можно запустить только его и открыть клиент.

```bash
docker compose up -d --wait clickhouse
docker compose exec clickhouse clickhouse-client --password lesson
```

В этом клиенте SQL из README уроков выполняется по порядку. Каждый урок создаёт свою базу. Для опыта доставки нужен запуск обоих сервисов по инструкции урока.

После завершения используется `docker compose down -v` из этого каталога. Эта команда удаляет данные учебного проекта. После нового запуска инструкция урока выполняется с начала.

## Публикация на Java

Программа `src/main/java/TripPublisher.java` читает строки событий из `trips.ndjson` и ждёт подтверждения каждой публикации Kafka. Maven и зависимости задаются в `pom.xml`, отдельная установка Java на компьютере не требуется. Сервис `publisher` запускается только по команде и завершается после публикации. Первый запуск загружает зависимости.

```bash
docker compose run --rm publisher
```

На пустом топике программа выводит `partition=0 offset=0` и `partition=0 offset=1`. Для повторной публикации только первого события используется тот же файл с ограничением в одну строку.

```bash
docker compose run --rm publisher mvn -q compile exec:java '-Dexec.args=trips.ndjson 1'
```

Повторная публикация создаёт новую запись Kafka с прежним `event_id`. В сырой таблице `source_topic`, `source_partition` и `source_offset` показывают положение доставки в журнале. Повторное чтение прежней записи сохраняет эти значения. Прежний `event_id` при новом `source_offset` означает повторную публикацию того же факта.
