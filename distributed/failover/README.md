# Переключение основной PostgreSQL

Отдельный опыт к урокам о передаче полномочий и автоматическом переключении. Он запускает три PostgreSQL под управлением Patroni, три участника etcd и HAProxy. Клиент сохраняет подтверждённые операции, поддерживает отдельное соединение со старой основной базой и сверяет данные после переключения.

Этот профиль перенесён из пилота курса. Он работает независимо от приложения бронирования в соседнем каталоге. Выделите Docker примерно 3 ГиБ памяти и четыре процессорных ядра. Нужны Node.js 26, Docker с Compose и сеть для первой сборки образа. Порты хоста не публикуются.

## Запуск

Из каталога _distributed_ соберите локальный образ Patroni. Он не публикуется в реестр.

```bash
docker build -t system-design-pilot-patroni:4.1.5 failover
```

Запустите четыре опыта. Каждому создаётся чистое состояние в отдельном проекте Compose с именем `sdp-<pid>`. Скрипт удаляет только созданные им ресурсы и сохраняет результаты в _reports/failover_.

```bash
node failover/run.ts
node failover/verify.ts
```

По умолчанию выполняется один повтор каждого опыта. Полный запуск с тремя повторами потребует согласованного изменения `repeats` в _criteria.json_, потому что проверяющий скрипт требует полный набор историй.

## Ожидаемые результаты

| Опыт | Условие | Категория результата |
| --- | --- | --- |
| `sql-fencing` | Клиент приостанавливается, преемник активирует следующее поколение, прежний клиент возвращается | `safe-fencing`, поздняя команда отвергнута и после перезапуска ресурса |
| `sync-network` | Основная база теряет сеть etcd, её Patroni продолжает работать | `safe-with-running-controller`, старое соединение теряет возможность записи, подтверждения сохраняются |
| `async-loss` | Репликация остановлена до записи, затем основная база потеряна | `acknowledged-data-loss`, проверка обнаруживает потерю трёх заданных подтверждений |
| `controller-pause` | Приостановлен только Patroni, PostgreSQL и старое соединение продолжают работать | `unsafe-stale-primary`, старая база принимает запись после переключения, затем эта запись теряется |

Последние два опыта намеренно показывают нарушение нужного свойства. Успех проверки означает обнаружение ожидаемого нарушения. Конфигурация с выключенным watchdog и приостановленным контроллером не обеспечивает единственность писателя.

Проверяющий скрипт читает JSON с подтверждениями клиента и снимками таблиц. Дополнительные отрицательные проверки подставляют потерянное подтверждение, повторный эффект и двойное назначение водителя. Они должны получить отказ проверки. Журналы процессов сохраняются для диагностики и не служат основанием для вывода о сохранности.

В JSON записываются идентификаторы образов, архитектура запуска и события. Порог запуска составляет 120 секунд, переключения 45 секунд. Эти пределы заданы для малого опыта. Перед выводом о другом окружении повторите запуск там.

Отказ облачной зоны, аппаратный watchdog и интеграция этого кластера с SAGA в данном профиле не проверяются. Сборка фиксирует основные версии PostgreSQL, Patroni, etcd и HAProxy; транзитивные Python-зависимости при повторной сборке могут измениться.
